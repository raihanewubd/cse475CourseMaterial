Lecture 5 — Performance Evaluation

ML-04: confusion matrix, accuracy, precision, recall, F1, the accuracy paradox, K-fold and stratified K-fold cross-validation
Rewritten as web notes from the CSE475 slide deck (22 slides), with every number recomputed; red boxes record corrections, blue boxes add what the slides leave implicit.

In one paragraph. Every classification metric in this lecture is arithmetic on four counts — true positives, false negatives, false positives, true negatives — so the confusion matrix comes first and the metrics follow. Accuracy is the share of correct predictions; precision asks whether a positive prediction can be trusted; recall asks whether the real positives were found; F1 is their harmonic mean. A worked disease-screening example gives all four from one matrix, a fraud example shows accuracy ranking a useless model first, and the last two tabs show why a single train/test split is not evidence and how K-fold and stratified K-fold cross-validation replace it. 1. Why evaluation needs more than one number, and the confusion matrix

A model is only as good as how you measure it

Slide 2
99%accuracy
0 of 10fraud cases caught

Same model, two very different stories.

A classifier that is correct 99% of the time can still be useless. Suppose 99% of transactions are legitimate. A model that labels everything legitimate scores 99% accuracy and catches zero fraud. The single number hides the failure entirely.

This lecture builds the tools that expose what accuracy hides: the confusion matrix, the four metrics derived from it, and a validation scheme that does not lie about rare classes.

The confusion matrix

Slide 3

Every prediction on a labelled test set lands in one of four buckets, formed by crossing what the model predicted with what was actually true. For binary classification that is a 2 × 2 table.

Convention used here: rows = actual class, columns = predicted class. scikit-learn's confusion_matrix uses the same orientation but orders the classes negative first (so TN sits top-left); some textbooks transpose the whole table. Always check which convention a source uses before reading TP off it.

Everything else — accuracy, precision, recall, F1 — is arithmetic on these four counts. Get the table right and the rest follows.

Four outcomes — two of them errors

Slide 4
OutcomeModel saysTruthReadingError type
True positive (TP)positivepositivea hit—
True negative (TN)negativenegativea correct rejection—
False positive (FP)positivenegativea false alarmType I
False negative (FN)negativepositivea missType II

Which error costs more depends on the problem: a false alarm wastes a follow-up; a miss can mean undetected cancer or fraud. Tab 4 returns to this.

Two derived quantities the slides do not name. The row totals are the class sizes: actual positives \(=\mathrm{TP}+\mathrm{FN}\), actual negatives \(=\mathrm{FP}+\mathrm{TN}\). The column totals are what the model predicted: predicted positives \(=\mathrm{TP}+\mathrm{FP}\), predicted negatives \(=\mathrm{FN}+\mathrm{TN}\). Precision divides by a column total, recall by a row total; keeping that straight is the whole trick to not mixing them up.

2. Worked example — four metrics from one matrix

Disease screening: the four counts

Slide 5

Setup. 100 patients tested; 10 actually have the disease (positive), 90 do not (negative).

  • 8 sick patients correctly flagged (TP)
  • 2 sick patients missed (FN)
  • 5 healthy patients false-alarmed (FP)
  • 85 healthy patients correctly cleared (TN)

Row totals: 10 sick, 90 healthy. Column totals: 13 flagged positive, 87 flagged negative. Every metric below comes from exactly these four numbers.

Accuracy

Slide 6
\[ \text{Accuracy}=\frac{\mathrm{TP}+\mathrm{TN}}{\mathrm{TP}+\mathrm{TN}+\mathrm{FP}+\mathrm{FN}}=\frac{8+85}{100}=\frac{93}{100}=\mathbf{93.0\%} \]

The share of all predictions that were correct — the diagonal of the matrix over the total. Simple and intuitive, but it treats every class and every error as equally important. Tab 3 shows what it does when one class dominates.

Precision

Slide 7
\[ \text{Precision}=\frac{\mathrm{TP}}{\mathrm{TP}+\mathrm{FP}}=\frac{8}{8+5}=\frac{8}{13}=\mathbf{61.5\%} \]

Of everything flagged positive, how much was right: "when the model raises an alarm, can I trust it?" Looks at the predicted-positive column (TP and FP). Low precision means many false alarms; it matters when acting on a positive is expensive.

Recall (sensitivity, true-positive rate)

Slide 8
\[ \text{Recall}=\frac{\mathrm{TP}}{\mathrm{TP}+\mathrm{FN}}=\frac{8}{8+2}=\frac{8}{10}=\mathbf{80.0\%} \]

Of all the real positives, how many the model caught: "does it miss the cases that matter?" Looks at the actual-positive row (TP and FN). Low recall means many misses; it matters when missing a positive is dangerous.

The mirror image: specificity. Recall is the true-positive rate. The same question asked of the negatives is specificity \(=\mathrm{TN}/(\mathrm{TN}+\mathrm{FP})=85/90=94.4\%\): of the healthy patients, how many were cleared. The slides never name it, but it is the metric that answers "F1 ignores true negatives" in tab 4, and (recall, 1 − specificity) are the two axes of an ROC curve.

F1-score

Slide 9
\[ F_1=\frac{2\,P\,R}{P+R}=\frac{2\cdot\frac{8}{13}\cdot\frac{8}{10}}{\frac{8}{13}+\frac{8}{10}}=\frac{16}{23}=\mathbf{69.6\%} \qquad\text{equivalently}\qquad F_1=\frac{2\,\mathrm{TP}}{2\,\mathrm{TP}+\mathrm{FP}+\mathrm{FN}}=\frac{16}{16+5+2}. \]

The harmonic mean of precision and recall. Why harmonic and not the plain average: it punishes imbalance. If \(P=1.0\) and \(R=0.0\), the plain average is 0.5 but \(F_1=0\). You only score high when both are high. Here the plain average would say 70.8%; \(F_1\) is lower because \(P\) and \(R\) differ.

Correction to the slides. Slide 9 writes the calculation as \(2\cdot(0.615\cdot0.80)/(0.615+0.80)\), which evaluates to 69.5%, and then prints 69.6%. The headline is right (the exact value is \(16/23=0.6957\)); the displayed arithmetic rounds \(P\) first and loses a tenth. Compute \(F_1\) from the counts, \(2\mathrm{TP}/(2\mathrm{TP}+\mathrm{FP}+\mathrm{FN})\), which never needs intermediate rounding — and is the form that makes "F1 ignores TN" visible at a glance.

3. When accuracy lies — the imbalanced case

Fraud detection: two models, two matrices

Slide 11

1000 transactions, only 10 are fraud (1% positive). Two models:

Model A — "always predict legitimate"

Accuracy = 990/1000 = 99.0%. Catches 0 fraud.

Model B — a real fraud model

Accuracy = 978/1000 = 97.8%. Catches 8 of 10 fraud.

The accuracy paradox

Slide 12
MetricModel A (lazy)Model B (real)Exact (B)
Accuracy99.0%97.8%978/1000
Precisionundefined (0/0)28.6%8/28 = 2/7
Recall0.0%80.0%8/10
F1-score0.0% (by convention)42.1%16/38 = 8/19
Specificity100%98.0%970/990
Balanced accuracy50.0%89.0%(0.8 + 0.9798)/2
Fraud caught0 of 108 of 10

Model A wins on accuracy and is worthless. Accuracy is dominated by the 99% majority class, so it rewards a model that ignores the minority. Recall exposes the failure (0% vs 80%); F1 confirms it (0 vs 42%). On imbalanced data, never rank models by accuracy alone.

Why "0.0%" for Model A's F1 is a convention, not arithmetic. With \(\mathrm{TP}=\mathrm{FP}=0\), precision is \(0/0\), so the \(2PR/(P+R)\) form of \(F_1\) is undefined too. The count form is not: \(F_1=2\mathrm{TP}/(2\mathrm{TP}+\mathrm{FP}+\mathrm{FN})=0/(0+0+10)=0\), perfectly defined. That is one more reason to compute \(F_1\) from counts. scikit-learn's f1_score returns 0 here and warns; precision_score returns 0 with a warning unless you set zero_division. Also shown: balanced accuracy \(=\tfrac12(\text{recall}+\text{specificity})\) is 50% for Model A — the value of a coin flip — which is the number accuracy should have reported.

4. Precision vs recall, the limits of F1, choosing a metric

Precision vs recall: the cost of each error

Slide 13

You can usually trade one for the other. Which one you protect depends on which mistake hurts more.

Spam filter → protect precision

False positive: a real email lands in spam — you miss something important.

False negative: spam reaches the inbox — mildly annoying.

The costly error is the false alarm, so tune for precision.

Cancer screening → protect recall

False negative: a tumour is missed — potentially fatal.

False positive: an extra test is ordered — inconvenient.

The costly error is the miss, so tune for recall.

The lever is the decision threshold. A classifier outputs a score; the label is "positive" when the score exceeds a threshold. Raise it and the model flags fewer cases: recall falls and precision usually rises. Lower it and recall rises while precision usually falls. There is no universally "right" metric — the cost of each error decides.

"Usually", not "always". Recall is monotone in the threshold (fewer flagged ⇒ never more hits). Precision is not: it can dip when raising the threshold drops a true positive before it drops a false positive. Over a whole precision–recall curve the trade-off holds; between two neighbouring thresholds it can briefly reverse.

F1 is useful, not magic

Slide 14
  1. It ignores true negatives entirely. \(F_1=2\mathrm{TP}/(2\mathrm{TP}+\mathrm{FP}+\mathrm{FN})\) has no TN term. Two problems with very different TN counts share the same F1; where correctly identifying negatives matters, F1 is silent. (Report specificity, or balanced accuracy, or MCC alongside it.)
  2. It weights precision and recall equally. If a miss costs 10× a false alarm, equal weighting is simply wrong for your problem.
  3. It hides which side is weak. A single F1 cannot tell you whether precision or recall is the problem. Always report both next to it.

When the costs are unequal, generalise with the \(F_\beta\) score:

\[ F_\beta=\frac{(1+\beta^2)\,P\,R}{\beta^2 P+R}, \qquad \beta>1\ \text{weights recall more (misses hurt)},\quad \beta<1\ \text{weights precision more (false alarms hurt)}. \]

On the disease example (\(P=8/13\), \(R=8/10\)): \(F_1=69.6\%\), \(F_2=75.5\%\) (closer to recall), \(F_{0.5}=64.5\%\) (closer to precision). \(\beta\) is the number of times recall is worth more than precision to you.

Choosing a metric

Slide 15

Rule of thumb: don't collapse to a single number before you understand the confusion matrix behind it.

More than two classes: macro and micro averaging

New

With \(C\) classes the confusion matrix is \(C\times C\), and precision/recall/F1 are defined per class by treating that class as positive and all others as negative. One summary number then needs an averaging rule:

AverageHowWhat it rewards
Macro-F1compute \(F_1\) for each class, take the plain meanevery class counts equally, however rare — a 1% class weighs as much as a 50% class. This is why the course project asks for macro-F1 on imbalanced datasets.
Micro-F1pool TP, FP, FN over all classes, then one \(F_1\)every sample counts equally; for single-label classification micro-F1 equals accuracy exactly, so it inherits the accuracy paradox.
Weighted-F1per-class \(F_1\) weighted by class sizea compromise; large classes still dominate.

scikit-learn: f1_score(y_true, y_pred, average='macro'); classification_report prints all per-class values plus the three averages.

5. Why one train/test split isn't enough — K-fold cross-validation

One split is one sample of a random variable

Slide 16
0.91"lucky" split
0.82"unlucky" split

Same model, two 80/20 splits (illustrative values).

A single 80/20 split gives one score, and that score depends on which 20% you happened to hold out. An easy split flatters the model; an unlucky one buries it. On small datasets the swing can be several points. You cannot tell skill from luck.

Which of 0.91 and 0.82 is the model's "true" score? Neither. Cross-validation fixes this: rotate the test set so every example is tested exactly once, then average the scores — and keep the spread, because the spread is information too.

K-fold cross-validation

Slide 17

Split the data into \(K\) (near-)equal folds. For \(k=1,\dots,K\): train on the other \(K-1\) folds, test on fold \(k\), record the score. Report the mean and the spread of the \(K\) scores.

Every sample appears in the training set \(K-1\) times and in the test set exactly once. Common choices: \(K=5\) or \(10\). Larger \(K\) means more training data per fold (less pessimistic bias) but \(K\) model fits and more correlated folds; \(K=N\) is leave-one-out.

Correction to the slides. Slide 17 says "every point trains the model K−1 times". A point does not train anything; it is in the training set of \(K-1\) of the \(K\) runs. The slide's wording invites the misreading that each point is used \(K-1\) times within one fit.

K-fold: reading the result

Slide 18

Same model, 5 folds, five accuracy scores: 0.85, 0.88, 0.82, 0.90, 0.86.

mean = 0.862

\((0.85+0.88+0.82+0.90+0.86)/5=4.31/5\). The estimate of true performance.

std = 0.027

How stable that estimate is. Deviations \(-0.012, +0.018, -0.042, +0.038, -0.002\); squares sum to 0.00368; \(\sqrt{0.00368/5}=0.0271\).

Report 0.862 ± 0.027, not one lucky number. A large spread is itself a finding: the model is sensitive to which data it sees.

Correction to the slides. The 0.027 is the population standard deviation (divide by \(K=5\); NumPy's default np.std). The sample standard deviation (divide by \(K-1=4\); np.std(ddof=1), pandas' default) is 0.030. Both are in use; the slide does not say which, and with five numbers the two differ by 12%. State the convention whenever you print "± std", and note that neither is a confidence interval — fold scores are correlated (they share training data), so \(\pm\) std/\(\sqrt{K}\) understates the real uncertainty.

6. Stratified K-fold — keep the classes balanced in every fold

Why plain K-fold can fail on imbalanced data

Slide 19

Plain K-fold splits at random. On imbalanced data that is dangerous: by chance a fold can end up with very few, or zero, minority examples, which makes recall undefined on that fold and the average unstable. Stratified K-fold forces every fold to hold the same class proportion as the full dataset.

How likely is the empty fold? (not on the slide, computed.) With 10 positives among 100 samples and \(K=5\), the chance that one particular fold of 20 gets no positive is \(\binom{90}{20}/\binom{100}{20}=9.5\%\). The chance that at least one of the five folds is empty is about 43% (200,000 simulated shuffles), and the chance that some fold has at most one positive is 98.6%. The left panel is not a rare accident; it is close to the typical case.

Default to stratified for any classification problem, and always for imbalanced ones — the same minority class that breaks accuracy also breaks a random split.

Stratified K-fold: the algorithm

Slide 20

Plain K-fold slices the whole index pool into \(K\) parts. Stratified slices each class into \(K\) parts, then merges, so every fold inherits the dataset's class ratio.

Input:   y = class labels for n samples;  K = number of folds
Output:  K folds, each holding the class proportions of y

1  Group sample indices by class
       for each class c in unique(y):
           bucket[c] = [ i : y[i] == c ]           # shuffle if wanted

2  Slice each class into K parts, merge part k into fold k
       fold[0..K-1] = empty
       for each class c:
           split bucket[c] into K near-equal parts  # sizes differ by <= 1
           for k in 0..K-1:   fold[k] += part[k]

3  Cross-validate                                   # identical to plain K-fold from here
       for k in 0..K-1:
           test  = fold[k]
           train = all indices not in fold[k]
           fit on (X[train], y[train]); score on (X[test], y[test])
       return mean(score), std(score)

Reference: Kohavi (1995) — the study that recommended ten-fold stratified CV for model selection. Implementation: scikit-learn StratifiedKFold.

Dataset: 10 positives + 90 negatives (10% minority), \(K=5\).

  1. Group by class: positives — 10 indices; negatives — 90 indices.
  2. Slice each class into 5 parts: \(10\div5=2\) positives per part; \(90\div5=18\) negatives per part.
  3. Merge part \(k\) of every class into fold \(k\): each fold = 2 pos + 18 neg = 20 samples.

Every fold: \(2/20=10\%\) positive, the ratio of the full dataset. Not divisible by \(K\)? Parts differ by at most one — e.g. 11 positives → 2, 2, 2, 2, 3.

Correction to the slides. Slide 21 prints "Every fold: 2 / 18 = 10% positive". \(2/18=11.1\%\); the 10% is \(2/20\), positives over the fold size, which is what "class proportion" means. Minor, but it is exactly the row-total vs column-total confusion the confusion-matrix tab warns about.
Granularity warning. With 2 positives per fold, per-fold recall can only be 0, 0.5 or 1.0, and per-fold precision is just as coarse. Stratification removes the empty-fold problem; it does not give you fine-grained minority metrics. With 10 positives in total, report pooled metrics (concatenate the out-of-fold predictions, then build one confusion matrix) or repeat the whole CV with several shuffles, rather than averaging five recall values that can each only take three values.
from sklearn.model_selection import StratifiedKFold
skf = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
for tr, te in skf.split(X, y):          # X may be a NumPy array or a torch tensor; y: labels
    train(X[tr], y[tr]);  evaluate(X[te], y[te])

PyTorch has no native stratified splitter — scikit-learn builds the index arrays; you index your tensors with them. split() only reads y and the length of X, so a tensor X is fine; keep y as a 1-D array or CPU tensor.

7. Summary, practice questions, references

What to carry out of this lecture

Slide 22
  1. The confusion matrix is the source. Accuracy, precision, recall and F1 are four questions asked of the same four counts.
  2. Accuracy alone misleads on imbalanced data — it can rank a useless model first. Report precision and recall too (and balanced accuracy or MCC if negatives matter).
  3. Precision asks "can I trust a positive?", recall asks "did I miss positives?" The costlier error picks your metric; \(F_\beta\) encodes the cost ratio.
  4. F1 balances the two but ignores true negatives and assumes equal cost; report P and R beside it. Compute it from counts, \(2\mathrm{TP}/(2\mathrm{TP}+\mathrm{FP}+\mathrm{FN})\).
  5. Validate with K-fold, and stratified K-fold when classes are imbalanced. Same villain — the minority class — in both metrics and validation. Report mean ± std and say which std.

Practice questions

New
  1. A spam filter on 500 emails gives TP = 60, FN = 15, FP = 10, TN = 415. Compute accuracy, precision, recall, specificity and F1 as exact fractions, then as percentages. Which metric would you lead with, and why?
  2. Show algebraically that \(2PR/(P+R)=2\mathrm{TP}/(2\mathrm{TP}+\mathrm{FP}+\mathrm{FN})\). Which of the two forms is defined when \(\mathrm{TP}=\mathrm{FP}=0\)?
  3. In the fraud example, Model C flags 50 transactions and catches all 10 frauds. Fill in its confusion matrix and compute accuracy, precision, recall and F1. Rank A, B and C by each metric; how many different rankings do you get?
  4. For the disease example, compute \(F_{0.5}\), \(F_1\) and \(F_2\) and explain in one sentence each which error cost they encode.
  5. Prove that recall never increases when the decision threshold is raised, and give a four-sample counter-example in which precision decreases when the threshold is raised.
  6. A dataset has 7 positives and 93 negatives. Write out the fold sizes (positives and negatives) that StratifiedKFold(n_splits=5) produces. What values can per-fold recall take?
  7. Five fold accuracies are 0.80, 0.84, 0.90, 0.78, 0.88. Compute mean, population std and sample std. Which would np.std give? Which would pandas.Series.std give?
  8. Explain why micro-averaged F1 equals accuracy for single-label multi-class classification, and why macro-F1 does not.
  9. With 10 positives in 100 samples and \(K=10\) plain K-fold, compute the probability that a given fold contains no positive. Is it higher or lower than for \(K=5\), and why?
