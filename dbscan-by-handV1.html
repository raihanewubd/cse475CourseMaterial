Part I · The original 10-point example

Two clusters, a border point and a noise point.

ε = 1.5 unitsMinPts = 4, including selfEuclidean distance

1 · Know the three rules

Core: at least 4 points in its ε-neighborhood, including itself.

Border: fewer than 4, but within ε of a core point.

Noise: neither core nor border.

A neighbor is any point at distance ≤ ε. Count the point itself. Only core points expand a cluster.

2 · Plot the data

Each grid square is 1 × 1. The coordinate table appears below. These are invented points for teaching.

3 · Calculate a few distances

d(P, Q) = √[(xP − xQ)² + (yP − yQ)²]

A(1,1) to B(1,2): √(0² + 1²) = 1 ≤ 1.5 → neighbors.

A(1,1) to D(2,2): √(1² + 1²) = √2 ≈ 1.414 ≤ 1.5 → neighbors.

A(1,1) to E(3,1): √(2² + 0²) = 2 > 1.5 → not neighbors.

C(2,1) to E(3,1): √(1² + 0²) = 1 ≤ 1.5 → neighbors.

So E can join A’s cluster through core point C. Points in one cluster do not all have to be within ε of each other.

5 · Grow the clusters by hand

  1. Choose an unvisited point. Find its ε-neighborhood, including itself.
  2. If it is core, start a cluster. Add all its neighbors.
  3. Inspect newly reached points. Add the neighbors of each core point to the same cluster.
  4. Keep border points, but stop expansion through them. They belong to the cluster because a core point reached them.
  5. Finish when no unchecked cluster members remain. Continue scanning other unvisited points. A non-core point outside a cluster is provisionally noise; it may later become border.

Scan in alphabetical order. At each core point, add its neighbors, then inspect newly reached points. The dashed circle is the current ε-neighborhood. Blue points lie inside that circle; colors here indicate proximity, not final clusters.

Part II · The seven-point reachability example

This is a separate dataset: point labels start again, coordinates change, and ε is now 1.2. All seven points form one cluster.

ε = 1.2 unitsMinPts = 4, including selfEuclidean distance

1 · The new dataset

A core point has at least 4 neighbors including itself. A border point has fewer than 4 but is within ε of a core point. A noise point is neither; this dataset has no noise points.

2 · Check the distances by hand

d(P,Q) = √[(xP − xQ)² + (yP − yQ)²]

A → B: √(1² + 0²) = 1 ≤ 1.2.

A → F: √(1² + 0.5²) = √1.25 ≈ 1.118 ≤ 1.2.

A → C: √(2² + 0²) = 2 > 1.2.

Thus N(A) = {A, B, E, F}: 4 points, so A is core.

3 · Directly density-reachable: one valid step

Q is directly density-reachable from P if P is core and d(P,Q) ≤ ε. The source P must be core; the destination Q may be core or border.

B is directly density-reachable from A: A is core and d(A,B) = 1. C is not directly density-reachable from A because d(A,C) = 2.

4 · Density-reachable: a chain of valid steps

Q is density-reachable from P if a chain leads from P to Q and each next point is directly density-reachable from the preceding point.

A → B → C → D is a valid chain: every step is 1 unit. A, B and C are core; D is border.

D is density-reachable from A, even though d(A,D) = 3 > ε. D is not directly density-reachable from A.

All points that pass expansion onward must be core. Only the final point may be border. The arrows show one valid path, not every connection in the dataset.

5 · Form the cluster, one decision at a time

  1. Choose an unvisited point and count its ε-neighborhood.
  2. If it is core, start a cluster and add all its neighbors.
  3. Inspect newly reached points. Expand through core points by adding their neighbors.
  4. Keep non-core points reached from a core point as border, but do not expand through them.
  5. Stop when there are no more points to inspect. Then scan for another unvisited point. A non-core point found outside a cluster is provisionally noise and may later become border.

Below, blue marks mean “already assigned to this cluster”; gray marks mean “not yet assigned.” Point shapes show the final core/border types. Newly assigned points still need their neighborhoods checked.

1. Inspect A → start cluster 1

N(A) = {A, B, E, F}, count 4. A is core. Assign A, B, E and F. Pending checks: B, E, F.

2. Inspect B → add C and G

N(B) = {A, B, C, E, F, G}, count 6. B is core. Add C and G. Pending checks: E, F, C, G.

3. Inspect E and F → no new members

E has 4 neighbors and F has 6; both are core. Their neighbors are already assigned. Pending checks: C, G.

4. Inspect C → add D

N(C) = {B, C, D, F, G}, count 5. C is core. Add D. Pending checks: G, D.

5. Inspect G and D → finish

G is core and adds nothing new. D has only {C, D, G}, count 3. Keep D as border; do not expand through it. No pending checks remain.

Final cluster = {A, B, C, D, E, F, G}. There is one cluster: six core points and one border point.

6 · Why the direction matters

D is directly density-reachable from C: C is core and d(C,D) = 1.

C is not directly density-reachable from D: D is not core, even though the distance is still 1. No nontrivial density-reachability chain can start from D.

Direct density-reachability is a special case of density-reachability. Neither relation is necessarily symmetric when a border point is involved.

Being in the same cluster does not require mutual density-reachability. A and D are density-connected: both can be reached from a common core point, such as B.

Check your understanding

If D is inspected before every other point, does it stay noise?

Reveal answer

No. D initially fails the core test and is provisionally marked noise. When C or G expands a cluster and reaches D, D becomes a border member. It still cannot expand the cluster.
