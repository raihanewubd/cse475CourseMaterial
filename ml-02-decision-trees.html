Lecture 3 — Decision Trees & Random Forests

ML-02: entropy, information gain, ID3, Gini, pruning, C4.5, random forests and boosting
Slides adapted from Radu Ionescu; rewritten as web notes with corrections and elaborations for CSE475.

In one paragraph. A decision tree asks one attribute at a time until it can name the class. This lecture shows how such a tree is learned from labelled data: entropy measures how mixed a set is, information gain measures how much a question un-mixes it, and ID3 always asks the question with the highest gain. The Gini alternative, the ID3 pseudo-code, pruning against overfitting, thresholds for numerical attributes, five ways to handle missing values, C4.5, and then random forests, bagging, random subspaces and boosting follow. Tab 2 carries three elaborations with two small interactive tools for building intuition about entropy and gain. Use the tabs to move between sections. Every slide is rewritten as text, tables and figures; the source slide numbers are shown on the right of each block. 1. What is a Decision Tree?

Definition

Slides 2–4
  • A decision tree is a tree-like model of a series of tests leading to decisions.
  • Each internal node tests one attribute; each branch is one outcome of that test; each leaf is a decision.

Applicant 1

  • Not a student · 45 years old · Medium income · Fair credit record

Student? No → Income? Medium → Credit Record? Fair → Age? > 40 → Yes.

Applicant 2

  • Student · 27 years old · Low income · Excellent credit record

Student? Yes → Income? Low → Credit Record? Excellent → Age? > 25 → No.

Prediction is a walk from the root to a leaf. Attributes not on the path are never read.

Decision Tree Learning

Slides 5–10
  • We use labelled data to obtain a suitable decision tree for future predictions.
  • We want a tree that works well on unseen data while asking as few questions as possible.
  • Basic step: choose an attribute and, based on its values, split the data into smaller sets. Repeat recursively until the label can be decided with certainty.

Entropy

Slide 14
  • Entropy measures the degree of randomness (mixing) in a set of labelled samples.
entropy(X) = − Σi=1..k pi log2(pi)

where pi is the proportion of elements of class i among the k classes in X.

  • For two classes: 0 when the set is pure, 1 bit when it is 50/50.
  • Lower entropy implies greater predictability.

Elaboration 1 — What the entropy number means

7-animal example

Entropy turns "pure vs. mixed" into a number you can compute. A pure node scores 0; a perfect 50/50 two-class node scores 1 bit. For the 7 animals (3 mammals, 4 birds):

entropy(X) = −(3/7) log2(3/7) − (4/7) log2(4/7) = 0.5239 + 0.4613 ≈ 0.985 bits

What the number means

0.985 sits just below the 1.0 maximum: almost a full bit of uncertainty is waiting to be removed by a good question. A set with 6 mammals and 1 bird would score 0.592; with 7 mammals, 0.

Why bits?

Because the log is base 2. One bit is one fair yes/no question's worth of doubt, which is why a 50/50 set scores exactly 1. Entropy is the average number of yes/no questions needed to pin down the label of a random element.

Watch out. A pure branch needs the term 0 · log2(0). Calculators say "undefined". Use the convention 0 · log 0 = 0, so a pure node has entropy exactly 0. (Formally, p log p → 0 as p → 0.)

Information Gain

Slide 15
  • The information gain of an attribute a is the expected reduction in entropy due to splitting on the values of a:
gain(X, a) = entropy(X) − Σv ∈ Values(a) ( |Xv| / |X| ) · entropy(Xv)

where Xv is the subset of X for which a = v. Read it as: entropy before the split minus the size-weighted average entropy after the split.

Elaboration 2 — Why the average after the split is size-weighted

reading the gain formula

The children are not the same size. A plain average pretends they are, and gives a number that does not describe the data. Worst case: a split sends 6 of 7 samples into a fully mixed branch (entropy 1.0) and 1 sample into a pure branch (entropy 0).

Plain average — wrong

(1.0 + 0) / 2 = 0.5

Fooled by the tiny pure branch: it looks like a decent split.

Weighted average — correct

(6/7)(1.0) + (1/7)(0) = 0.857

Knows that almost everything is still stuck in the mixed branch.

The reason it must be weighted. "Entropy after the split" answers: if I pick a random sample, how much uncertainty is it now sitting in? A sample is more likely to land in a bigger branch, so the branch sizes are probabilities. The weights |Xv|/|X| in the gain formula are exactly those probabilities, which makes the second term an expected value: the expected entropy after asking about a.

Elaboration 3 — Compare the two splits, then pick the winner

the rule inside ID3

Entropy before the split is computed once (0.985). Whichever attribute leaves the least mixing after the split wins the largest gain.

ID3 picks Fly? — it removes about 26 times more uncertainty than Color. Both branches of Color stay muddy, so the average barely moves; the one pure branch of Fly? pulls the average down to 0.464. This single comparison is the line a = select_attribute_with_highest_information_gain(X) in the pseudo-code: at every node the tree greedily asks the question that buys the biggest immediate drop in uncertainty, then recurses on each child.

Branch 1: Branch 2:

The one idea to keep

  1. Entropy = mixing. Pure node 0, perfect 50/50 = 1 bit. It makes "messy" computable.
  2. Gain = mixing removed. Entropy before minus the size-weighted entropy after. A big gap is a good split.
  3. Weight by branch size. Otherwise one clean outlier branch can fake a good split.
  4. Pick the highest gain. That greedy choice is the entire attribute-selection rule in ID3.

Swap entropy for Gini and gain for impurity decrease and the selection rule is identical (next tab). Measuring purity and chasing its biggest reduction is the point.

3. Gini Impurity

Gini Impurity

Slide 25
  • Gini impurity measures how often a randomly chosen element would be incorrectly labelled if it were labelled at random according to the label distribution.
gini(X) = 1 − Σi=1..k pi2

where pi is the proportion of elements of class i.

  • Same shape as entropy but lower: maximum 0.5 for two classes.
  • Can be used as an alternative to entropy for selecting attributes (this is what CART does).

Entropy versus Gini Impurity

Slide 27
  • Entropy and Gini impurity give similar results in practice.
  • They disagree on the chosen attribute in only about 2% of cases — "Theoretical Comparison between the Gini Index and Information Gain Criteria" (Răileanu & Stoffel, AMAI 2004).
  • Entropy may be slower to compute because of the logarithm.

def make_tree(X):
    node = TreeNode(X)
    if should_be_leaf_node(X):
        node.label = majority_label(X)
    else:
        a = select_best_splitting_attribute(X)
        for v in values(a):
            X_v = {x ∈ X | x[a] == v}
            node.children.append(make_tree(X_v))
    return node

ID3 Algorithm (Python)

Slide 23, moved
# ID = Iterative Dichotomiser
def ID3(X):
    node = TreeNode(X)
    if all_points_have_same_class(X):
        node.label = majority_label(X)
    else:
        a = select_attribute_with_highest_information_gain(X)
        if gain(X, a) == 0:
            node.label = majority_label(X)
        else:
            for v in values(a):
                X_v = {x ∈ X | x[a] == v}
                node.children.append(ID3(X_v))
    return node
  • Leaf test: all points share a class, or no attribute has positive gain. Leaf label: majority class.
  • Split rule: the attribute with the highest information gain (Quinlan, 1986); one child per attribute value; recurse on each child.

5. Pruning

Pruning

Slide 29
  • Pruning reduces the size of a decision tree by removing branches that provide little predictive power.
  • It is a regularisation method: a smaller tree is a less complex model, which reduces overfitting. Decision trees are prone to overfitting.
  • Pre-pruning: stop the tree-building algorithm before it fully classifies the data.
  • Post-pruning: build the complete tree, then replace some non-leaf nodes by leaves if this improves validation error.

Pre-pruning

Slide 30
  • Pre-pruning is early stopping: if some condition is met, the current node is not split even though it is not 100% pure.
  • It becomes a leaf with the label of the majority class in the current set; the class distribution can be reported as prediction confidence.
  • Common stopping criteria are thresholds on the entropy (or Gini impurity) of the current set, the number of samples in it, the gain of the best attribute, or the depth of the tree.
  • Example: a node with 54 Yes / 5 No becomes a leaf "Yes" with confidence 54/59 ≈ 91.5%.
Correction. The slide's entropy(54|5) = 0.29 is a natural-log value (0.290 nats). With the log2 definition used throughout the lecture, entropy(54|5) = 0.419 bits, which is above θent = 0.4, so the illustrated stop would not fire. Read the example with θent = 0.5; the mechanism is unchanged. (54/59 = 91.53%, printed as 91.52%.)

Post-pruning

Slides 31–33
  • Prune nodes in a bottom-up manner if it decreases the validation error.
  • As nodes are pruned, training error rises while validation error first falls and then rises. Stop at the minimum of the validation curve.

7. Missing Values & C4.5

Handling missing values at training time

Slides 45–50
  • Datasets might have samples with missing values for some attributes (shown as ?). Simply ignoring those samples would throw away a lot of information. Better ways:
Does it fly?ColorClass
No?Mammal
NoWhiteMammal
?BrownBird
YesWhiteBird
NoWhiteMammal
NoBrownBird
YesWhiteBird

Row 1 has no Color, row 3 has no Fly? value.

1. Set them to the most common value

Among known rows Fly? is 4 No / 2 Yes and Color is 4 White / 2 Brown, so row 1 → White and row 3 → No.

2. Set them to the most probable value given the label

Row 1 is a Mammal: P(White | Mammal) = 1, P(Brown | Mammal) = 0 → White. Row 3 is a Bird: P(Yes | Bird) = 2/3, P(No | Bird) = 1/3 → Yes. (Uses the label, so training time only.)

3. Add a new instance for each possible value

Row 1 becomes (No, White, Mammal) and (No, Brown, Mammal); row 3 becomes (Yes, Brown, Bird) and (No, Brown, Bird): 7 rows become 9. C4.5 does a weighted version, giving each copy a fractional weight equal to the value's frequency.

4. Leave them unknown, but discard the sample when evaluating the gain of that attribute

For Color, use the 6 rows where Color is known: brown = 2 birds (entropy 0); white = 2 mammals + 2 birds (entropy 1). If the attribute is chosen for splitting, send the instances with unknown values to all children.

parent on the 6 known rows: 2 mammals, 4 birds → entropy = 0.918     gain(X, color) = 0.918 − (2/6)·0 − (4/6)·1 ≈ 0.252   (C4.5 then scales by the known fraction 6/7: 0.216)
Correction. The source slide computes gain(X|color) = 0.985 − (2/6)·0 − (4/6)·1 = 0.318, taking entropy(X) over all 7 rows but the child weights over the 6 known rows; the two must be computed on the same rows. The corrected value is above. The slide's notation also slips from gain(X, a) to gain(X|a) — same quantity.

5. Build a decision tree on all other attributes (including the label) to predict the missing values

Train each tree on the instances where the attribute is defined. Row 1 (Mammal) → White; row 3 (Bird, Brown) → No.

Handling missing values at inference time

Slides 51–52
  • When we encounter a node that checks an attribute with a missing value, we explore all possibilities.
  • We follow every branch and take the final prediction from a (weighted) vote of the corresponding leaves. C4.5 weights each branch by the fraction of training rows that went down it.

Student? No → Income is unknown, so both branches are explored: High → Age > 30 → Yes; Medium → Credit Record Fair → Age > 40 → Yes. Both leaves say Yes → Yes.

C4.5 Algorithm

Slide 53
  • C4.5 (Quinlan, 1993) extends ID3 with several improvements:
  • Handles both categorical and numerical attributes (continuous attributes are split at the best threshold).
  • Handles missing values at training time (not used when gain is computed) and at inference time (all corresponding branches are explored).
  • Handles attributes with different costs.
  • Post-pruning, bottom-up, removing branches that increase validation error (i.e. that hurt generalisation).
Correction. One improvement is missing from the source slide, and it is the one that changes the split rule: C4.5 selects attributes by gain ratio = gain(X, a) / splitInfo(X, a), where splitInfo is the entropy of the attribute's own value distribution. Plain gain favours attributes with many values (a day-ID column would look like a perfect split). On PlayTennis the correction nearly changes the root: gain ratio is Outlook 0.156, Humidity 0.152, Wind 0.049, Temperature 0.019.

History of Decision Trees

Slide 56
  • First regression-tree algorithm: Automatic Interaction Detection (AID), Morgan & Sonquist, 1963.
  • First classification-tree algorithm: THAID, Messenger & Mandell, 1972.
  • Decision trees become popular: CART, Breiman et al., 1984.
  • ID3: "Induction of Decision Trees", Quinlan, 1986.
  • C4.5: "C4.5: Programs for Machine Learning", Quinlan, 1993.

Summary

Slide 57
  • Decision trees are a tool based on a tree-like graph of decisions and their possible outcomes.
  • Decision-tree learning is a machine-learning method that uses a decision tree as the predictive model.
  • ID3 builds the tree by iteratively splitting the data on the attribute with the largest information gain (decrease in entropy); the decrease in Gini impurity is a commonly used alternative.
  • C4.5 extends ID3 to continuous attributes and missing values, and adds regularisation by pruning branches likely to overfit.

9. Random Forests & Ensembles

Random Forests

Slide 59
  • Instead of building a single decision tree, build many slightly different trees and combine their predictions.
  • We have a single dataset, so how do we obtain slightly different trees?
  • 1. Bagging (Bootstrap Aggregating): draw N bootstrap samples of the training set and fit a decision tree on each.
  • 2. Random Subspace Method (feature bagging): fit N trees, each constrained to a random subset of the features.
Correction. The source slide says bagging takes "random subsets" to create "N smaller data sets". A bootstrap sample has the same size as the training set and is drawn with replacement, so about 63% of the rows appear (some more than once) and about 37% are left out. Random Forests — putting it together

Slides 64–65
  • Random subspace method: "Random Decision Forests" (Ho, 1995) and "The Random Subspace Method for Constructing Decision Forests" (Ho, 1998).
  • Bagging combined with random subspaces, and the term Random Forest (a trademark of Leo Breiman and Adele Cutler): "Random Forests" (Breiman, 2001).
Precision note: the random subspace method as drawn picks one feature subset per tree (Ho, 1998). Breiman's random forest picks a fresh random subset of features at every split; that per-split randomness is what decorrelates the trees. scikit-learn's max_features is this per-split parameter.

Ensemble Learning and Boosting

Slides 66–72
  • Ensemble learning combines multiple learning algorithms to obtain performance improvements over its components. Random forests are one of the most common examples.
  • Bagging: multiple models on random subsets of samples. Random subspace method: multiple models on random subsets of features.
  • Boosting: train models iteratively, making the current model focus on the mistakes of the previous ones by increasing the weight of misclassified samples.
  • AdaBoost weights each model by its accuracy; gradient boosting instead adds models that fit the residual error.

Summary — ensembles

Slide 73
  • Ensemble methods combine multiple learners to beat any one of them: bagging, random subspace method, boosting.
  • Random forests build multiple decision trees through bagging and the random subspace method; averaging many trees cuts the variance that makes a single tree overfit.
"They rectify the overfitting problem of decision trees" (source slide) is stronger than what a forest guarantees: averaging reduces variance, but a forest of fully grown trees can still fit label noise. Keep the pruning tools in mind.

from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import RandomForestClassifier

clf = DecisionTreeClassifier(criterion="entropy", min_samples_leaf=3)
# criterion = "gini" / "entropy"; max_depth; min_impurity_decrease; ...
clf.fit(X, y)              # numerical features; encode categoricals first
clf.predict([x])           # predict the class of x
clf.feature_importances_   # importance of each feature
clf.tree_                  # the underlying tree object

clf = RandomForestClassifier(n_estimators=20)   # random forest with 20 trees
Correction. Three things on the source slide are out of date or misleading for current scikit-learn and are changed above. (1) min_impurity_split was removed in scikit-learn 1.0; the parameter is min_impurity_decrease. (2) LabelEncoder is meant for the target; encode categorical features with OrdinalEncoder or OneHotEncoder. (3) scikit-learn's tree is CART: every split is binary even with criterion="entropy", so it will not produce the three-way Outlook split of ID3. Since version 1.3 it also accepts missing values (NaN) in fit.
